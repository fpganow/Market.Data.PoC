## 5. New LabVIEW -> Linux transfer workflow (proposal, not yet set up)

Today the LabVIEW PC's working tree is mirrored to ASUS15 by OneDrive (read-only here) and exports
land in `C:\NIFPGA\compilation` on the same PC. Without OneDrive on the Linux box, two things must
travel:

1. **Source VIs** -> commit and push from the LabVIEW PC (`git add -A submodules fpga host *.lvproj
   && git commit && git push`), `git pull` on Linux. This also closes the gap in §3 (21 modified
   VIs that exist only on the LabVIEW PC). The owner's convention of delivering `*.generated.vi`
   beside the originals in both trees stays, just via git.
2. **The IP export** (`C:\NIFPGA\compilation\market.data.poc_FPGATarget_poc.ip.kria_*\source_files\
   NiFpgaAG_poc_ip_kria.dcp` + `NiFpgaIPWrapper_poc_ip_kria.vhd`, ~4 MB) -> `scp` into
   `Market.Data.PoC/ip_export/` on Linux (or commit it from the LabVIEW PC: the `.dcp` is
   LFS-tracked, the `.vhd` is plain text). Then on Linux: `make local-gen-poc_ip_kria`,
   `make ip-install-poc_ip_kria`, `ports_from_dcp.py ... --check`, `sim_all.sh`, `make xsa-clean && make xsa`.

Either `scp` from the LabVIEW PC (it needs the Linux box's ssh host key and a key pair), a shared
SMB folder on the Linux box, or a `git lfs` push. The `make ip-export-list/copy-N` targets that
scan `/mnt/c/NIFPGA/compilation` can be pointed at a mounted share by editing `ip_export/Makefile`
line ~15/81 or simply replaced by the scp step.
