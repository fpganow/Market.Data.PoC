Three implementations of the same Cboe PITCH parser run on the AMD Kria KR260 in the same 10 Gigabit Ethernet harness. They are the "parser implementation" choices on the Run on Hardware page and the subjects of the Benchmarks page. All three take a PITCH multicast frame off the wire and emit one normalised 16 × 64-bit record per message (type, side, order id, quantity, symbol, price, executed/cancelled/remaining, timestamps), so the same host tools read all of them. Source: github.com/fpganow/Market.Data.PoC.

The shared harness

Models 2 and 3 share one Vivado block design: the XXV 10G Ethernet subsystem, XGMII-to-AXI-Stream adapters, AXI DMA, capture FIFOs, GPIO control and the Zynq MPSoC configuration all live in vivado/. The Verilog project sources that design and swaps the LabVIEW netlist cell for the RTL parser, so a harness improvement reaches both. The host side (apps/poc_server, apps/poc_inject/poc_mon, scripts/) and the test captures and scorer are common too.

Model 2: LabVIEW FPGA IP export

  • Parser: a 100 MHz LabVIEW single-cycle loop (bats.parser.vi) fed through a 156.25 MHz-to-100 MHz FIFO; 14 message types; one 64-bit word of the record per cycle.
  • Build: edit and "IP Export" in LabVIEW on Windows, convert the checkpoint to Verilog, then make ip-install-poc_ip_kria && make xsa-clean && make xsa in Vivado 2024.1 on Linux, make kria-build kria-stage kria-deploy-staged kria-load-app for the board.
  • Open the design: make -C vivado gui, or in Vivado's Tcl console cd vivado; source mktdata_poc.tcl.
  • Limit: the 16-word record serialisation (160 ns per message, 6.25 M msg/s); the optimisation plan is in optimize.txt.

Model 3: pure Verilog

  • Parser: everything in the 156.25 MHz receive clock. Ethernet/IPv4/UDP filter and payload re-aligner, a 64-word FIFO with whole-frame drop, a one-word-in/one-message-out extractor, a field decoder, one 1024-bit record beat per message. 2.3k LUTs, no block RAM.
  • Build: make rtl-sim (xsim, scored), make rtl-xsa, make rtl-kria-build rtl-kria-stage rtl-kria-deploy-staged rtl-kria-reload-app.
  • Open the design: make -C vivado_rtl gui, or cd vivado_rtl; source mktdata_rtl.tcl.
  • Diagrams (data flow, state machines, flow charts, class diagram): vivado_rtl/DIAGRAMS.md.
  • Written with an AI coding assistant against the LabVIEW design as the reference; it is the reference implementation for porting the optimisations back into LabVIEW.

Switching models on the board

sudo xmutil listapps
sudo xmutil unloadapp
sudo xmutil loadapp mktdata_rtl      # or mktdata_poc

Both packages live under /lib/firmware/xilinx/ on the KR260 and load in about a second without reflashing. The 10G link only comes up while one of them is loaded, because the XXV PCS must transmit.
